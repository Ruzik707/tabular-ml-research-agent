# Повторное сравнение агентов после исправлений Universal

Завершено 25.10.2026 (Москва). Выполнены 32 запуска агентов: 20 для итоговой матрицы, 4 свежих старого Universal, 4 новых synthetic и 4 сохранённых диагностических; также 12 контрольных моделей. Финальная версия Universal зафиксирована **до её контрольных запусков**: `1dd19b50188dfd64047bcf5a73339bd87bfde9c5`.

Предыдущее [сравнение от 23 октября](https://github.com/aprelskiyegor/alfa_hackathon/blob/a8fb14ad8ac7c669f4acc8b52a7fb446c5fcc330/universal_agent/docs/AGENT_COMPARISON.md) сохранено в истории. Измеренные результаты, версии и контрольные суммы публикуются в [AGENT_COMPARISON_RESULTS.json](AGENT_COMPARISON_RESULTS.json).

**Финальная версия сформировала четыре валидных CSV и завершила все четыре full-data refit.** Исправленный multiclass-промпт дошёл до LLM; ошибка контекста больше не прерывает финализацию. Universal приблизился к сильным донорам на классификации и проверяет линейное семейство на старте, но лидером всех задач не стал. Его сильная сторона — проверяемый протокол и сохранение результата; качество поиска и полезность локальной LLM ещё требуют развития.


В первом диагностическом цикле версия `8188bfc` столкнулась с функциональной ошибкой на multiclass: после четырёх успешных trials обязательный промпт размером 9150 символов не вместился в жёсткий лимит 9000. CSV checkpoint был валиден (Macro F1 0.60607), но финальное обучение пропущено. Исправлены мягкий/жёсткий лимиты контекста и обработка ошибки до отправки запроса: она не списывает токены и не должна прерывать host search/finalization. Добавлены synthetic behavioral tests и replay фактического контекста с сохранением всех классов/base IDs. Параметры моделей/разбиения/scorer при этом не менялись.

Четыре диагностических запуска `8188bfc`, включая этот сбой, сохранены отдельно в JSON и не используются как результаты финальной версии. Основная матрица ниже объединяет 16 неизменных донорских запусков первого цикла и 4 повторных запуска финального Universal `1dd19b5` в тех же условиях. Все четыре результата новой версии заменяются целиком; лучший результат из разных версий по каждой задаче не выбирается. Для фаз отдельно сохранены source pins, SHA и конфигурации.

Число trials не является само по себе мерой качества: разные агенты используют разную стоимость экспериментов, repeated holdout и локальный tuning. Финальная public-регрессия Universal выбрала локальный ExtraTrees, full refit занял 22.007 с; резерв предоставил около 40.4 с. На multiclass выбран host LightGBM со sqrt_balanced и fit-only частотами/индикаторами; cross-fitted мета-проверка приняла небольшую смесь двух LightGBM-рецептов с коррекцией классов. Два участника обучены заново на всех 70529 строках за 8.523 с. Внешний Macro F1 0.63664 относится к итоговой смеси. Без отдельной ablation нельзя приписать весь выигрыш только весам, признакам или ансамблю.

На synthetic linear выбран локальный Ridge(alpha=0.1); binary — sqrt_balanced LightGBM с локальным min_child_samples=30. Все full refit успешны. В binary предложение threshold≈0.28918 было отклонено по meta assessment и **не применялось**: рост внешнего F1 нельзя объяснять применённым точным порогом.

Работа с LLM улучшена технически, но её вклад ограничен: в финальных четырёх запусках 91 успешный trial, из них 3 LLM-origin (1 linear, 2 binary); ни один LLM-рецепт не стал итоговым лидером. В regression предложения отклонялись по неподдержанным операциям/fit options. В multiclass валидные предложения пришли, когда окно исследований уже заканчивалось, и не были исполнены. Асинхронность даёт полезные host fits во время ожидания, но не гарантирует время на каждую вернувшуюся LLM-гипотезу.

Для Universal proxy зафиксировал 9 HTTP-запросов, 7 ответов, но host использовал только 5 ответов. 37 332 токена — серверная статистика, включая ответы после отмены; 108 248 — учёт host с консервативными резервами для неизвестного usage. Эти числа не являются рублёвой стоимостью и не должны подменять друг друга. Поздняя отмена освобождает ожидание клиента; отдельный proxy/server может закончить запрос позже. Полные статус/время/метрики и происхождение сохранены в JSON.

## Что изменилось и откуда взяты идеи

Подробная карта «идея → исходный файл → новая реализация» находится в [PROVENANCE.md](PROVENANCE.md). Новые решения используют те же разрешённые зависимости; алгоритмы четырёх доноров не исправлялись.

| Подтверждённая проблема | Исправление | Источник и границы переноса |
|---|---|---|
| CatBoost занимал 120 с первым; другим моделям и LLM не хватало времени | CV warmup: LightGBM → Linear/Ridge → ExtraTrees → XGBoost → CatBoost; ограничен долей research-окна | Дешёвый Linear и локальный tuning Ruzik, быстрые playbooks Oleg/Rakovskiy; дорогие семейства перенесены в конец |
| В стартовом плане не было Linear при доступных бустерах | Ridge(alpha=1) остаётся в стартовом списке при доступных бустерах; локальный поиск alpha=0.1/1/10; масштабирование и imputation только на fit | Ruzik 85f4988, models.py/search.py; предыдущая независимая Ridge дала RMSE 20.3691 на линейном примере |
| Полезная балансировка была доступна, но не проверялась рано | Измеренный LightGBM получает отдельную sqrt_balanced-гипотезу для Macro/Binary F1; затем одна попытка fit-only frequency/missing chain | Oleg researcher.py; нормальная host-оценка, fingerprint dedup; частоты/индикаторы только по X fit-fold, веса классов только по y fit-fold; внешний target/test не используются для обучения статистик |
| Резерв уменьшался до 9.44 с; final worker получал 4.37/0.69 с | Полное окно = measured fit×1.5 + отдельные 8 с startup + write overhead от 5 с; минимальный резерв короткого запуска и строгая проверка допуска | Исправление подтверждённой ошибки Universal; legacy 15% startup API сохранён, длинный бюджет не ограничивается коротким trial cap |
| Дорогой trial мог занять почти всё исследование | Стабильный cap=min(requested, total/6, remaining_research−2); scheduler отдельно защищает резерв | Для 180 с это до 30 с на trial, для 3 часов — до 1800 с; при недостатке времени сохраняется checkpoint |
| Ожидание LLM останавливало поиск | HTTP выполняется в фоне, основной поток продолжает ограниченный воспроизводимый host search и единолично ведёт журнал/состояние | Сильные локальные поиски доноров объединены с проверяемым ядром Aprelskiy; фактическое происхождение trials сохраняется |
| Batch из 2 гипотез отклонялся при 1 worker | Proposal limit 2 отделён от concurrency 1/2; валидные кандидаты исполняются очередью | Без увеличения суммарных CPU/RSS; дедупликация и временные/числовые лимиты сохранены |
| Промпт около 10.8k токенов занимал 53 с | Убраны дубли контекста/истории; сохранены metric/positive class, измеренные base IDs, параметры лучшей модели и допустимые диапазоны каталога | Compact fallback не может удалять все base IDs; содержимое JSON остаётся валидным |
| Поздняя отмена могла потеряться при входе в complete() | Отдельный cancellation token создаётся до запуска потока, связывается с запросом и закрывает HTTP task | Сигнатура complete() сохранена, unknown/billable outcomes резервируют токены консервативно; это не точная цена API |
| Принятый ансамбль проверялся по окну одиночной модели | Выбор мета-постобработки и финальный admission считают стоимость фактических активных участников, startup и запись | Cross-fitted F1 threshold/ensemble проходят раздельную cross-fitted мета-проверку; это не nested CV; вероятности не меняются порогом |

Supervised target encoding, causal history/lag и подбор entity key из доноров **не копировались целиком**. Их перенос требует отдельной проверки вложенного выбора признаков и временных/групповых границ. Этот эксперимент проверяет конкретно реализованные изменения, а не весь потенциальный feature space.

Полный свежий набор: **543 passed,2 ожидаемых sklearn ConvergenceWarning, exit0 за 119.32 с**. Предыдущий исходный baseline:499passed; целевой baseline перед реализацией 53passed. Existing assertions не ослаблялись: обновлены только точные ожидания новой политики и fixtures, которым теперь необходим полный measured plan/корректная Linear-схема.

## Воспроизведение

Команды от корня репозитория, при готовой venv, публичных исходных данных и запущенной Ollama с указанным digest:

```bash
git fetch origin main aprelskiy_branch oleg_branch rakovskiy_branch ruzik
.venv/bin/python universal_agent/scripts/compare_agents.py \
  --repo /path/to/alfa_hackathon --data-root /path/to/alfa_hackathon \
  --workspace /tmp/alfa-comparison-v2-new --seed 42 --threads 2 \
  --public-budget 180 --supplemental-budget 60 \
  --universal-ref 1dd19b50188dfd64047bcf5a73339bd87bfde9c5
.venv/bin/python universal_agent/scripts/benchmark_reference.py \
  --workspace /tmp/alfa-comparison-v2-new --threads 2
```

Для matched synthetic проверки используйте новый workspace, `--agents universal --seed 43 --cases synthetic-signed-linear-regression synthetic-imbalanced-binary-f1`; запустите отдельно со старым `--universal-ref 91ad0a2078be0613562bd7642cab33936ff6ad64` и новым ref выше. Нельзя одновременно выполнять эти измерения или примешивать результаты разных конфигураций в один workspace.

Четыре исходных holdout уже использованы для диагностики и разработки, поэтому новый выигрыш на них — повторная development-проверка.
