# Подробный разбор задания

Источник: локальный PDF «Альфа Хак_AutoML», 20 страниц; прочитан полностью. Текст извлечён по страницам; интерфейс, ограничения и формулы страниц 6, 7, 18, 19 дополнительно проверены по рендеру. baseline.py изучен из all_agents/ruzik; оба публичных task.md и data_dictionary.csv сверены с файлами.

## Суть и критерии поведения (стр. 2, 4–5, 11–15)

Нужен автономный исследователь, который понимает условие и цель, анализирует данные, строит признаки, выбирает модели и валидацию, выдвигает гипотезы, исполняет эксперименты, анализирует ошибки и сохраняет лучший результат. Выдуманная LLM метрика не является доказательством; обязательна проверка по train-only валидации. Состояние экспериментов и причины решений должны позволять проследить цикл. Одно/несколько ролей разрешены; фиксированный AutoML-перебор сам по себе не раскрывает агентную часть.

Тот же неизменный код должен переноситься на новые задачи. Поэтому в универсальном runtime нет ветвлений по site_eui, attack_cat, именам публичных папок или классам атак. Задачи сверх single-target supervised CSV требуют отдельного контракта; PDF не раскрывает форматы private и не даёт оснований обещать поддержку произвольного ML.

## Интерфейс и поставка (стр. 6, 16–17; baseline.py)

- На платформу передаётся ZIP; в его корне solution.py. Можно включить импортируемые модули.
- Интерфейс: Python entrypoint получает путь task.md; входные относительные пути считаются от каталога Markdown; submission.csv пишется рядом с ним. Для каждого задания отдельный процесс.
- baseline использует OPENAI_API_KEY, OPENAI_MODEL, OPENAI_BASE_URL и инструменты Python. Его MCP — реализация базового инструмента, а не отдельное обязательное требование к архитектуре. Universal вызывает свои контролируемые инструменты напрямую.
- Агент получает только материалы текущей задачи. Файлы/результаты одной задачи в следующую не передаются. Никакой обратной связи по скрытому тесту для промежуточных гипотез нет.
- Не более трёх отправок в сутки на команду, обновление в 00:00 по Москве. Код автоматически не отправляет сабмитов на платформу.
- Private: две новые задачи, содержание и метрики заранее неизвестны. Платформа выбирает сохранённую последнюю версию с лучшим public score и запускает solution.py с новым условием. Код менять между задачами нельзя.

## Ограничения (стр. 7–8)

Python 3.12; Docker; 8 CPU, 32 GB RAM; не более 3 часов с запуска. К cutoff уже должен существовать корректный файл предсказаний: успешные предыдущие модели нельзя держать только в памяти до конца исследования. Universal пишет ранний fallback, сохраняет каждого лидера и ограничивает final fit оставшимся временем.

Для обучения разрешены только предоставленные данные и модели/библиотеки из requirements.txt. Внешние train-данные, скачивание предобученных ML-моделей и интернет из контейнера запрещены. Другие модели через собственные API-ключи запрещены. Для разработки организаторами заявлены Qwen3.8-27B и командный дневной денежный лимит 600 рублей. Запуск на пользовательской локальной Ollama — текущий способ разработки без ключа; доступность такой службы на платформе не предполагается. При выдаче API используются переменные baseline. Локальный token cap не является контролем общего командного расхода в рублях.

Разрешено самостоятельно распределять бюджет между гипотезами, признаками, алгоритмами, схемами валидации, тюнингом, ансамблями и финальным обучением. Нельзя считать разрешение исследовать валидацию разрешением менять её между сравниваемыми кандидатами ради более высокого числа.

## Публичные данные (стр. 9–10 и task.md)

Общий комплект: train.csv, test.csv, data_dictionary.csv, sample_submission.csv. UTF-8, запятая, десятичная точка; пустые клетки — пропуски.

| Задача | Train / test | Признаки | Target и метрика | Ответ |
|---|---:|---:|---|---|
| Энергопотребление зданий | 53308 / 22449 | 62 + id | site_eui; RMSE в исходной шкале kBtu/ft² за год | id,site_eui |
| Тип сетевой атаки UNSW-NB15 | 87670 / 41166 | 42 + id | attack_cat; Macro F1; Accuracy/Weighted F1 справочные | id,attack_cat |

Регрессия: здание в определённом периоде; погода известна за тот же год. Year_Factor — анонимизированный период, year_built — календарный год, их нельзя просто вычитать как возраст здания. id не подтверждён как постоянный идентификатор здания. Ветер в угловых градусах не является температурой. В train периоды 1–5, test период 6: это основание проверять перенос во времени. Эти факты выведены из входов, а не зашиты в runtime.

Классификация: десять классов Normal, Generic, Exploits, Fuzzers, DoS, Reconnaissance, Analysis, Backdoor, Shellcode, Worms. Сильный дисбаланс; равный вес классов в Macro F1 отличает его от Accuracy. label отсутствует как явная утечка normal/attack. Категории proto/service/state; `-` означает отсутствие сервиса. Test взят из отдельного официального hold-out; стратификация не делает распределения train/test одинаковыми.

Оба публичных ответа: ровно по строке на test ID, в порядке test; без дополнительного индекса, пропусков, бесконечностей, дублей ID и посторонних классов. Нули в sample не правильные ответы. Имеющиеся submission пользователя не использовались как labels и не переписывались тестовыми прогонами.

## Оценка (стр. 18–19)

RMSE = sqrt(mean((y - prediction)²)), меньше лучше. Macro F1 — среднее F1 по классам с одинаковыми весами, больше лучше.

При baseline BRMSE > 0 и BF1 < 1:

- Sreg = 100 × max(0, 1 - RMSE / BRMSE).
- Scls = 100 × max(0, (MacroF1 - BF1) / (1 - BF1)).
- Public score = (Sreg + Scls) / 2; задачи равновесны; диапазон 0–100.
- Private score — среднее баллов двух новых задач; их метрики могут отличаться, нормирование соответствует метрике.

Baseline-качество на скрытых target не дано. Локальный OOF нельзя подставлять вместо платформенного hidden-test score и объявлять достигнутый leaderboard результат. Адаптивный выбор и postprocessing по OOF не создают независимого теста.

## Что остаётся проверить на платформе

Реальные env/endpoint выданной Qwen, доступность всех пакетов базового образа, финальный private evaluator и hidden-test метрики. Системные ограничения контейнера должны обеспечивать сеть/файлы/память независимо от Python-проверок. Публичные локальные прогоны, unit tests и ZIP smoke подтверждают конкретные контракты; они не заменяют платформенную проверку.
